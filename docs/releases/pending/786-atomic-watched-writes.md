# fix(storage): writes into FileWatcher-scanned directories are atomic, and promotion compensation stops blocking the event loop (#786)

## What changed
Draft Room documents and ordinary uploads share one ingestion front door: the vault upload directories `FileWatcher` scans. Three write paths streamed or copied bytes straight onto FINAL paths inside those directories, so a process kill mid-write left a truncated file the next scan permanently ingested; and draft-promotion's failure compensation cancelled queued ingestion jobs synchronously from an async frame, performing a blocking pooled-DB checkout on the event loop that the surrounding 30-second budget could not interrupt.

- **Every watched-directory write is now temp-sibling + `os.replace`** (`app/services/atomic_write.py` is the one canonical pattern `.{name}.{uuid4hex}.part` for producers writing into a scanned directory): document upload streams to a temp sibling and validates (OOXML member, image decode, size) BEFORE any bytes are placed at the final path (the path still holds a 0-byte reservation placeholder for the write's duration, as below); draft promotion copies/renders promoted bytes to a temp and replaces onto the reserved placeholder only after the size check; startup `migrate_uploads` size-checks its temp copy before placing it. The name-reservation creates (`O_CREAT|O_EXCL`) no longer carry a write flag — a reservation is not a byte write.
- **`FileWatcher._find_new_files` skips canonical temp artifacts** (exact generated shape only — a user's `.notes.part` in a library dir is still enqueued), so a kill- or cancel-leftover temp can never be ingested.
- **Upload failure paths clean both artifacts** — placeholder and temp — including the `CancelledError` a client disconnect delivers mid-stream, which previously bypassed every cleanup handler.
- **Promotion's write step is two-phase**: the worker thread only writes the temp; `os.replace` runs on the event loop strictly after the write completes, so a cancellation mid-copy can never let a detached thread place unregistered bytes at the watched path after compensation already ran (a bounded background reaper removes any leftover temp once the detached worker signals completion). Developed after empirical probes showed shielding a `to_thread` await cannot hold: cancelling a task awaiting an executor future cancels the wrapper immediately while the thread keeps running.
- **Compensation's job cancellation went off the event loop**: `BackgroundProcessor.cancel_pending_jobs_async` runs the lease-mode jobs-row pass (blocking pooled checkout + SQL) via `asyncio.to_thread`; the in-memory `asyncio.Queue` drain deliberately stays on the event loop (the queue is not thread-safe and the drain must stay atomic wrt the workers). The sync `cancel_pending_jobs` contract is unchanged for `request_ingest_cancel` and existing callers. Both entry points refuse an empty match (an unguarded empty lease-mode call would cancel every pending job).

## Behaviour change worth knowing
A kill mid-write now leaves a canonical dot-prefixed `.part` file (watcher-skipped, never ingested) instead of a truncated document. During a long upload the final path holds a 0-byte placeholder for the write's duration; the scan screen rejects empty files, and on a crash the placeholder name-squats until the next attempt. A cancelled promotion unwinds promptly: the detached copy thread's canonical `.part` residue is removed by a bounded background reaper once the worker signals completion, and correctness is preserved because the loop-side `os.replace` onto the watched path never runs after cancellation.

## Migration
No schema or settings change. No restart required.

`backend/security/bandit-baseline.json` is re-anchored for pure line drift from the edits above (131 findings, signature multiset unchanged; only `line_number` moved).

## Caveats
- Two same-class write sites are intentionally out of this issue's named scope and remain as before: the email poller's `email_<random><ext>` mkstemp attachments written directly into watched vault dirs (email_service.py), and `request_ingest_cancel`'s synchronous contract, which still performs its lease-mode checkout on the caller's thread (issue #783 pinned it "synchronous BY CONTRACT").
- The legacy one-shot vault-path migration (`migration.vault_paths.done`, database.py) copies whole directory trees non-atomically; it is flag-gated to run once ever per deployment and outside this issue's three named sites.
- Cancellation-time temp cleanup on Windows is best-effort (a briefly-open executor handle can defer an unlink); residue is always a watcher-skipped canonical `.part`.
- **Residue accumulates on disk.** Only draft promotion reaps its own temp. An upload or migration temp left by a hard kill (SIGKILL, power loss) is never removed, and `migrate_uploads` runs on every process start, minting a fresh temp per attempt — so repeated hard kills during startup migration accumulate unbounded, unreferenced `.part` files in vault upload directories. They are never ingested (the watcher skips the exact shape) and never surface as errors; only disk space is affected. Cleanup of these is follow-up work.
- The #645 AST guard (`tests/test_issue645_no_on_loop_checkout.py`) still passes, but its reach was not extended: the barrier rule treats an intervening sync `def` as safe, so a future caller that invokes a synchronous pooled checkout straight from an async frame stays invisible to it. Extending the guard is follow-up work.
