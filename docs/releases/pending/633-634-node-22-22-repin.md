# 633/634 — Node runtime re-pin 22.14 → 22.22 (issues #633/#634 docker bumps)

## What changed

The Node.js runtime pin moves minor-exact **22.14 → 22.22** across every
contract surface, per the re-pin procedure encoded in
`scripts/check_runtime_contract.py`:

- `scripts/check_runtime_contract.py` — `ALLOWED_RUNTIME["node"].minor = "22"`
- `.github/workflows/ci.yml` (3 jobs) and
  `.github/workflows/nightly-quality-gates.yml` — `setup-node` `22.22.0`
- `frontend/Dockerfile` and root `Dockerfile` —
  `FROM node:22.22-alpine@sha256:e58326d0...` (digest-pinned, absorbing the
  dependabot docker bumps #634/#633)
- `frontend/package.json` `engines.node` — `>=22.22.0`
- `.devcontainer/devcontainer.json` + `post-create.sh`,
  `backend/tests/test_devcontainer_contract.py`, `CONTRIBUTING.md`,
  `INSTALLATION.md`, `justfile` — aligned

## Why

Node 22.14 is the minor-exact contract pin; 22.22 is the same LTS major
line. The re-pin unblocks dependency majors whose engine floors exceed
22.14 (jsdom 30 needs `^22.22.2`; stryker 10's Babel-8 transitive tree
needs `^22.18.0`).

## Migration steps

Local dev environments need Node ≥ 22.22.0 (`frontend/package.json`
engines enforces it). No application-code changes.

## Known caveats

- The devcontainer feature pin and CI setup-node move to `22.22.0`
  together; a stale local nvm version below 22.22 fails `npm ci` engine
  checks by design.
